01Resumen del proyecto

El aprendizaje del código Morse suele apoyarse en tablas y aplicaciones que no ofrecen una referencia física de cómo se construye cada carácter. Este proyecto desarrolla un entrenador portátil de código Morse integrado en una sola PCB: el usuario introduce puntos y rayas con un único pulsador y 27 LEDs, dispuestos según el árbol binario del código (incluida la Ñ), muestran la posición alcanzada. Un Arduino Nano (ATmega328P, 5 V, 16 MHz) controla el sistema; cuatro registros de desplazamiento 74HC595 en cascada manejan los LEDs con solo tres líneas del microcontrolador (MOSI, SCK y LATCH), y un buzzer pasivo accionado con un transistor 2N3904 entrega la retroalimentación sonora. El equipo se alimenta con una batería externa de 7–12 V por el pin VIN, sin depender del USB. En este segundo avance se rediseñó la arquitectura respecto al primer entregable (de un ATmega328P-AU a 3.3 V con carga Li-Po a un Arduino Nano a 5 V), se completaron el esquemático y la PCB de dos capas de 166 × 128 mm en EasyEDA y se actualizó el modelo 3D en Onshape con una carcasa de bordes redondeados. Se presentan el listado de componentes, el diseño electrónico, el plan de validación de entradas y salidas, dos sketches de prueba y firmware base, y la estimación de consumo (≈ 27 mA en reposo y ≈ 17 h de autonomía con una batería de 9 V de 500 mAh).

03Descripción del proyecto

3.1Concepto y principio de funcionamiento

El entrenador es un dispositivo físico, autónomo y portátil que enseña la estructura del código Morse de forma espacial. El usuario introduce las secuencias de puntos y rayas con un único pulsador y, a medida que lo hace, se enciende el LED que corresponde al nodo alcanzado en el árbol binario del código Morse. De esta manera se “recorre” el árbol visualmente y se asocia cada letra con su ubicación y con su secuencia.

  • Entrada: pulsador SW1 con discriminación temporal: pulsación corta (< 250 ms) = punto; pulsación larga (≥ 250 ms) = raya. Un condensador de 100 nF (C5) en paralelo con el pulsador reduce el rebote por hardware.

  • Visualización: 27 LEDs (26 letras del alfabeto latino más la Ñ) ubicados siguiendo el árbol Morse sobre una malla de 12 mm × 10 mm. Los LEDs se controlan con cuatro registros 74HC595 en cascada.

  • Retroalimentación sonora: buzzer pasivo accionado mediante PWM con un transistor 2N3904; el tono confirma cada elemento introducido y distingue acierto de error.

  • Autonomía: funciona con una batería externa de 7–12 V conectada a J1 (VIN del Arduino Nano). El USB se usa únicamente para programar y depurar.

3.3Modos de uso

El firmware base (Anexo A.2) define dos modos de operación:

  • Modo 1 – Práctica libre: cada pulsación avanza por el árbol y enciende el LED del nodo actual con su tono. Tras 700 ms sin pulsar, el carácter se da por terminado: el LED de la letra parpadea dos veces y el árbol vuelve a la raíz.

  • Modo 2 – Reto: el equipo elige una letra al azar y reproduce su código por el buzzer. El usuario lo repite con el pulsador. Si acierta, parpadea el LED y suena una melodía ascendente; si falla, suena un tono grave, parpadea el LED de la letra correcta y se repite el código.

  • Cambio de modo: pulsación larga (≥ 1.5 s) con el árbol vacío.

3.5Alimentación

La batería externa se conecta a J1 y alimenta el pin VIN del Nano, cuyo regulador integrado genera el riel de +5 V que usan el microcontrolador, los cuatro 74HC595 y el buzzer. Cada 74HC595 tiene un condensador de desacople de 100 nF (C1–C4). Para la demostración final no se usa el USB. El diseño actual no incluye un interruptor general de encendido: se registra como mejora en la sección 9.3.

3.6Carcasa / frame

La carcasa modelada en Onshape es rectangular, de aristas redondeadas, con tapa superior sobre la que se ubican: las ventanas rectangulares de cada LED, dispuestas en árbol y con la letra correspondiente grabada junto a cada una; el rótulo “LOS CAPOS”; y el pulsador, que se acciona con una tapa sobredimensionada y biselada en la esquina superior derecha para facilitar la pulsación. La PCB (166 × 128 mm) se fija con tornillos M3 a través de sus tres orificios de montaje. Dimensiones externas y espesor de pared: 190x150x40mm

3.7Criterios de validación

  • El riel de +5 V se mantiene entre 4.75 V y 5.25 V con la batería conectada y sin USB.

  • Los 27 LEDs encienden individualmente y cada uno corresponde a la letra rotulada en la carcasa.

  • El pulsador clasifica correctamente punto (< 250 ms) y raya (≥ 250 ms) en al menos 18 de 20 pulsaciones de prueba.

  • El buzzer es audible y el transistor no se calienta durante el uso continuo.

  • El equipo completa un ciclo de entrenamiento (mostrar, recibir respuesta y dar retroalimentación de acierto/error) funcionando solo con batería.

  • La PCB cabe en la carcasa y los LEDs y el pulsador quedan alineados con sus aberturas.

04Objetivos

4.1Objetivo general

Diseñar, fabricar y validar un entrenador portátil de código Morse integrado en una única PCB, alimentado por batería, que permita practicar la introducción de caracteres con un pulsador, visualizar el recorrido en un árbol de 27 LEDs y recibir retroalimentación sonora de acierto y error.

4.2Objetivos específicos

  • Definir y justificar la arquitectura de hardware (Arduino Nano, registros 74HC595, driver de buzzer y alimentación externa) frente a las alternativas consideradas.

  • Diseñar el esquemático y la PCB de dos capas en EasyEDA, ubicando los 27 LEDs en la disposición del árbol Morse y garantizando que todo el sistema resida en la misma tarjeta.

  • Modelar en Onshape el dispositivo completo (PCB, componentes, batería y carcasa) con dimensiones coherentes con el diseño electrónico.

  • Desarrollar y validar el firmware: discriminación punto/raya con umbral de 250 ms, recorrido del árbol, modo práctica, modo reto y retroalimentación sonora.

  • Estimar y medir el consumo en reposo y en uso para calcular la autonomía con batería.

  • Documentar las pruebas, los errores encontrados y las mejoras realizadas durante el desarrollo.

Los 27 códigos de la tabla se verificaron contra el alfabeto Morse internacional y se comprobó que cada prefijo de un código corresponde a otra letra del árbol, de modo que en todo momento hay un LED que encender mientras el usuario introduce un carácter.

6.5Alimentación, desacople y protección

  • Desacople: C1–C4 de 100 nF, uno por cada 74HC595, ubicados junto a su pin de alimentación; C5 de 100 nF filtra el pulsador.

  • Corriente de LEDs: con Vf ≈ 2.0 V y R1 = 2.2 kΩ: I ≈ (5 V − 2.0 V − caída de salida) / 2.2 kΩ ≈ 1.3–1.4 mA, valor bajo y seguro para el 74HC595 y el pin de cada salida.

  • Driver del buzzer: Q1 2N3904 con R28 de 1 kΩ: Ib ≈ (5 − 0.7) V / 1 kΩ ≈ 4.3 mA, suficiente para saturar el transistor con una carga de decenas de mA.

  • Disipación del regulador del Nano: con 9 V de entrada y 30 mA, P ≈ (9 − 5) V × 0.03 A = 0.12 W, valor bajo para el regulador del módulo.

08Firmware

8.1Lógica general

  • Lectura del pulsador: INPUT_PULLUP en D2, con filtrado por hardware (C5) y descarte por software de pulsaciones menores a 30 ms.

  • Clasificación: se mide con millis() el tiempo que se mantiene presionado: < 250 ms es punto y ≥ 250 ms es raya.

  • Árbol Morse: el código acumulado (hasta 5 elementos) se busca en una tabla de 27 entradas ordenada igual que la cadena de 74HC595; el resultado es directamente el LED que debe encenderse.

  • Salida a los LEDs: se envía una palabra de 32 bits con shiftOut() (primero el byte de U5) y se genera el pulso en LATCH.

  • Fin de carácter: 700 ms sin pulsar. Si el código no existe o supera 5 elementos se indica error.

  • Sonido: tone() sobre D3 a 800 Hz mientras se pulsa; melodía ascendente para acierto y tono de 200 Hz para error.

8.2Código

El código fuente comentado se incluye en el Anexo A: el sketch de validación de entradas y salidas (A.1) y el firmware base con los modos de práctica y reto (A.2). Ambos compilan sin errores de sintaxis en una verificación con un entorno simulado y deben cargarse en el Nano para obtener los resultados de la sección 9.

9.2Estimación de consumo y autonomía

La estimación usa valores típicos de referencia y debe contrastarse con la prueba P7. Se supone una batería de 9 V con 500 mAh y un regulador lineal, de modo que la corriente de la batería es aproximadamente la corriente consumida en el riel de 5 V.

Escenario Composición Corriente (mA) Autonomía (h)
Reposo Nano ≈ 25 mA + 74HC595 ≈ 0.4 mA + 1 LED ≈ 1.4 mA ≈ 27 ≈ 18.5
Uso normal Reposo + buzzer ≈ 15 mA al 10 % del tiempo ≈ 28.5 ≈ 17.5
Peor caso Reposo + buzzer sonando de forma continua ≈ 42 ≈ 11.9

Medidas para mejorar la autonomía (bonificación de optimización de consumo): apagar los LEDs tras un periodo de inactividad, usar el modo de bajo consumo del ATmega328P con despertar por la interrupción del pulsador, retirar el LED de encendido del Nano y limitar el tiempo y el volumen del buzzer.

10Conclusiones

  • Pasar de un ATmega328P-AU soldado en la PCB a un Arduino Nano simplificó el diseño: se eliminaron el cristal, el circuito de reset y programación, el cargador y el regulador, a cambio de una tarjeta más grande y un mayor consumo base.

  • Los cuatro 74HC595 en cascada permiten controlar los 27 LEDs del árbol Morse con solo tres pines, y quedan 5 salidas libres para ampliaciones.

  • Compartir una resistencia de 2.2 kΩ en el retorno de los LEDs ahorra 26 componentes, siempre que el firmware encienda un solo LED a la vez.

  • La estimación indica una autonomía cercana a 17 horas con una batería de 9 V; el valor real debe confirmarse con la prueba P7.

  • Antes de fabricar se deben cerrar las observaciones 1, 2 y 4 del registro de errores (conexión sin enrutar, interruptor general y paso de las huellas).

  • Para el avance final quedan por completar la fabricación y el ensamble, las mediciones reales de consumo, la carcasa impresa y el video de demostración.

A.1 Sketch de validación de entradas y salidas

validacion_io.ino 
// ============================================================
// Entrenador Morse - SKETCH DE VALIDACION DE ENTRADAS Y SALIDAS
// Placa: Arduino Nano (ATmega328P, 5 V, 16 MHz)
// Prueba 1: barrido de los 27 LEDs en el orden de la cadena 74HC595
// Prueba 2: buzzer (tonos de 800 Hz y 600 Hz)
// Prueba 3: pulsador (clasifica punto / raya con umbral de 250 ms)
// ============================================================
const uint8_t PIN_PULSADOR = 2; // SW1, INPUT_PULLUP (activo en bajo)
const uint8_t PIN_BUZZER = 3; // R28 1k -> base de Q1 2N3904
const uint8_t PIN_LATCH = 7; // RCLK de los 4 x 74HC595
const uint8_t PIN_MOSI = 11; // SER del primer 74HC595 (U2)
const uint8_t PIN_SCK = 13; // SRCLK de los 4 x 74HC595
const unsigned long UMBRAL_RAYA_MS = 250;
// Indice de cadena: 0-7 = U2 (QA..QH), 8-15 = U3, 16-23 = U4, 24-26 = U5
// '#' representa la letra Ñ
const char LETRAS[27] = {
  'H','S','I','E','T','M','O','#', // U2
  'V','P','W','L','R','A','F','U', // U3
  'Q','G','Z','N','K','Y','C','D', // U4
  'X','B','J' // U5
};
// Enciende un unico LED (idx 0..26). idx = -1 apaga todos.
void mostrarLED(int8_t idx) {
  uint32_t v = (idx >= 0) ? (1UL << idx) : 0UL;
  digitalWrite(PIN_LATCH, LOW);
  for (int8_t b = 3; b >= 0; b--) { // primero el byte de U5
    shiftOut(PIN_MOSI, PIN_SCK, MSBFIRST, (v >> (8 * b)) & 0xFF);
  }
  digitalWrite(PIN_LATCH, HIGH);
}
void setup() {
  pinMode(PIN_PULSADOR, INPUT_PULLUP);
  pinMode(PIN_BUZZER, OUTPUT);
  pinMode(PIN_LATCH, OUTPUT);
  pinMode(PIN_MOSI, OUTPUT);
  pinMode(PIN_SCK, OUTPUT);
  Serial.begin(9600);
  // Prueba 1: barrido de LEDs
  for (int8_t i = 0; i < 27; i++) {
    mostrarLED(i);
    Serial.print("Indice "); Serial.print(i);
    Serial.print(" -> LED "); Serial.println(LETRAS[i]);
    delay(300);
  }
  mostrarLED(-1);
  // Prueba 2: buzzer
  tone(PIN_BUZZER, 800, 150); delay(300);
  tone(PIN_BUZZER, 600, 450); delay(600);
  Serial.println("Listo: pulse SW1 para la prueba de punto/raya");
}
void loop() {
  // Prueba 3: pulsador
  if (digitalRead(PIN_PULSADOR) == LOW) {
    unsigned long t0 = millis();
    tone(PIN_BUZZER, 700);
    while (digitalRead(PIN_PULSADOR) == LOW) { }
    noTone(PIN_BUZZER);
    unsigned long dt = millis() - t0;
    if (dt >= 30) { // descarta rebotes
      Serial.print(dt);
      Serial.println(dt < UMBRAL_RAYA_MS ? " ms -> PUNTO" : " ms -> RAYA");
    }
    delay(30);
  }
}

A.2 Firmware base: práctica libre y reto

firmware_base.ino 
// ============================================================
// Entrenador Morse - FIRMWARE BASE (practica libre + reto)
// Arduino Nano (5 V). Un solo pulsador, 27 LEDs en arbol Morse.
// - Pulsacion < 250 ms = punto, >= 250 ms = raya
// - Pausa de 700 ms sin pulsar = fin de caracter
// - Pulsacion larga (>= 1500 ms) con el arbol vacio = cambia de modo
// ============================================================
const uint8_t PIN_PULSADOR = 2, PIN_BUZZER = 3;
const uint8_t PIN_LATCH = 7, PIN_MOSI = 11, PIN_SCK = 13;
const unsigned int UMBRAL_RAYA_MS = 250;
const unsigned int FIN_CARACTER_MS = 700;
const unsigned int PULSO_MODO_MS = 1500;
// Codigos en orden de cadena 74HC595 (indice = salida del LED)
const char* const CODIGOS[27] = {
  "....","...","..",".","-","--","---","--.--", // H S I E T M O Ñ (U2)
  "...-",".--.",".--",".-..",".-.",".-","..-.","..-",// V P W L R A F U (U3)
  "--.-","--.","--..","-.","-.-","-.--","-.-.","-..", // Q G Z N K Y C D (U4)
  "-..-","-...",".---" // X B J (U5)
};
char codigo[8];
uint8_t n = 0;
bool modoReto = false;
int8_t objetivo = -1;
void mostrarLED(int8_t idx) {
  uint32_t v = (idx >= 0) ? (1UL << idx) : 0UL;
  digitalWrite(PIN_LATCH, LOW);
  for (int8_t b = 3; b >= 0; b--) shiftOut(PIN_MOSI, PIN_SCK, MSBFIRST, (v >> (8 * b)) & 0xFF);
  digitalWrite(PIN_LATCH, HIGH);
}
int8_t buscar(const char* c) {
  for (uint8_t i = 0; i < 27; i++) if (strcmp(c, CODIGOS[i]) == 0) return i;
  return -1;
}
void pitidoOK() { tone(PIN_BUZZER, 700, 100); delay(130); tone(PIN_BUZZER, 1000, 100); delay(130); tone(PIN_BUZZER, 1400, 160); delay(200); }
void pitidoERR() { tone(PIN_BUZZER, 200, 450); delay(500); }
void parpadear(int8_t idx, uint8_t veces) {
  for (uint8_t i = 0; i < veces; i++) { mostrarLED(idx); delay(150); mostrarLED(-1); delay(150); }
}
void reproducir(int8_t idx) { // suena el codigo del objetivo
  for (const char* p = CODIGOS[idx]; *p; p++) {
    tone(PIN_BUZZER, 800); delay(*p == '.' ? 120 : 360); noTone(PIN_BUZZER); delay(120);
  }
}
void nuevoReto() { objetivo = random(27); delay(400); reproducir(objetivo); }
void setup() {
  pinMode(PIN_PULSADOR, INPUT_PULLUP);
  pinMode(PIN_BUZZER, OUTPUT);
  pinMode(PIN_LATCH, OUTPUT); pinMode(PIN_MOSI, OUTPUT); pinMode(PIN_SCK, OUTPUT);
  randomSeed(analogRead(A0));
  mostrarLED(-1);
}
void loop() {
  static unsigned long tSuelta = millis();
  if (digitalRead(PIN_PULSADOR) == LOW) {
    unsigned long t0 = millis();
    tone(PIN_BUZZER, 800);
    while (digitalRead(PIN_PULSADOR) == LOW) { }
    noTone(PIN_BUZZER);
    unsigned long dt = millis() - t0;
    tSuelta = millis();
    if (dt < 30) return; // rebote
    if (n == 0 && dt >= PULSO_MODO_MS) { // cambio de modo
      modoReto = !modoReto;
      pitidoOK();
      if (modoReto) nuevoReto();
      return;
    }
    if (n < 5) {
      codigo[n++] = (dt < UMBRAL_RAYA_MS) ? '.' : '-';
      codigo[n] = '\0';
      mostrarLED(buscar(codigo)); // LED del nodo actual
    }
  }
  if (n > 0 && millis() - tSuelta > FIN_CARACTER_MS) { // fin de caracter
    int8_t idx = buscar(codigo);
    if (idx < 0) { pitidoERR(); }
    else if (!modoReto) { parpadear(idx, 2); }
    else if (idx == objetivo) { parpadear(idx, 3); pitidoOK(); nuevoReto(); }
    else { pitidoERR(); parpadear(objetivo, 2); reproducir(objetivo); }
    n = 0; codigo[0] = '\0'; mostrarLED(-1);
  }
}
